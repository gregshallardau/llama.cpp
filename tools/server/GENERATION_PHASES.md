# Experimental generation-phase observer

This experimental observer is **passive**. It does not create checkpoints, change
the sampler, edit prompts, or invalidate the KV cache.

## Usage

Configure delimiter strings for the model's *actual generated text*, for example:

```sh
LLAMA_PHASE_REASONING_START='<think>' \
LLAMA_PHASE_REASONING_END='</think>' \
LLAMA_PHASE_TOOL_START='<tool_call>' \
LLAMA_PHASE_TOOL_END='</tool_call>' \
./build/bin/llama-server --model /path/to/model.gguf
```

The example delimiters are not universal. Do not enable them without checking the
model's chat template and generated token stream. A delimiter may be a text string,
multiple tokens, or absent entirely. Tool calls encoded in separate message metadata
cannot yet be detected by this plain-text observer.

The server writes transitions to its existing logs:

```text
generation phase changed: phase=reasoning byte_offset=0 token_id=...
generation phase changed: phase=response byte_offset=100 token_id=...
generation phase changed: phase=tool_call byte_offset=110 token_id=... (checkpoint candidate; KV not saved)
```

Each actual line includes the checkpoint-candidate clarification. The offset
is measured in generated bytes for the current slot response and **is not a KV
position**. No phase event changes the ordinary HTTP streaming payload.
